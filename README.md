# 上海康肯销售订单管理系统

用于维护上海康肯销售订单、设备、发货、开票与回款数据的本地桌面应用。应用以 SQLite 关系数据库为唯一权威数据源，并可导出「导航页 + 未回收管理表 + 各 JOB 页」Excel 台账。

## 可靠性设计

- 六张订单业务表及报价单/报价明细存入本地 SQLite；合同 JOB、发货批次、设备归属和报价明细归属由外键与唯一约束保护。
- 保存使用单个事务与修订号乐观锁：业务校验、关系约束、数据库检查失败或另一窗口已保存时整体回滚，不会部分写入/覆盖新版。
- 每次写入前在数据库同目录的 `备份/` 创建快照，保留最近 10 份。
- 数据库启用 WAL、完整同步、外键检查和修订号；设置页可见当前修订与完整性状态。
- 从旧 `*.records.json` 首次迁移时创建同目录 `.db`，原 JSON 保留不动；未知关联/公式字段存入扩展 JSON，不会在迁移中丢失。
- 文本导出会转义 Excel 公式前缀，避免内容被 Excel 当作公式执行。
- 审计从功能启用时的数据库修订建立基线，不回填 legacy 历史；此后的新增、删除和实质字段修改与业务数据在同一事务写入。
- 审计事件保存操作人、入口来源、应用版本、设备与字段旧值/新值；记录只追加，并通过连续 SHA-256 哈希链检测修改或删除。

## 日常工作流

1. macOS 双击 `启动.command`；Windows Release 完整解压后双击 `BKTC_Ledger.exe`，源码包双击 `启动.bat`（会在 `data/` 缺失时创建空白数据库及其初始 Excel 导出文件）。
2. 首次使用可直接打开发布包内的数据库，或在「设置」选择本地 `.db`（也可选择旧 `*.records.json` 自动迁移）；选择会保存到当前用户配置并在下次启动恢复。
3. 推荐点「＋ 新建订单」，一次填写订单头、设备、首批发货和付款条件，自动建立六表记录与稳定记录 ID。
4. 在六个业务页编辑；五张子表的客户由 JOB 自动带入，批次合计、合同汇总、验收状态、应收日、回款状态和超期天数都会自动重算。
5. 点「保存数据库」；有错误时应用会切回摘要页并拒绝写入。
6. 点「导出台账」从数据库重建同目录、同文件名的 `.xlsx`；旧台账自动进入 `备份/`。
7. 需要报价时进入「报价单」：可选择来源 JOB 自动带入客户、担当者、全部型号/数量/未税单价、送货地点和付款条件，补齐商务条款后保存并导出标准报价 XLSX。

## 数据库与 Excel

应用只关联数据库，不关联独立的 Excel 文件。数据库 `example.db` 的完整台账始终导出为同目录下的 `example.xlsx`；外部修改 Excel 不会回写数据库。「📥 导出 Excel」用于导出当前单表的筛选/排序结果，同样只是报表文件。报价单也先保存到同一数据库，再从数据库中的已保存版本生成到 `Downloads/报价单/`，示范模板本身不会被修改或作为数据源。

## 变更审计

1. 首次使用前在「设置」确认“当前操作人”；默认取本机系统用户名。
2. 新建订单、各业务录入、表格修改、删除和批次关联操作，会在下一次成功保存时形成审计事件。
3. 在「审计记录」按日期、操作人、JOB、来源、业务表或操作类型查询，并查看字段旧值与新值。
4. 「查询并验证」会重新计算整条哈希链；异常时页面明确报警。审计记录可导出为 XLSX。

自动派生字段不会产生无意义噪音；关联改名与后台重算造成的持久化变化会分别标记为“关联同步”或“系统重算”。保存失败时业务数据和审计记录一起回滚。SQLite 文件由本机持有，哈希链用于发现篡改，不能替代受控服务器或数字签名提供的法律级不可抵赖性。

## 主要操作

- 筛选/排序：点列名排序；点 `▾` 勾选值；后续列只显示当前 JOB、客户及其他筛选条件下仍可用的值。客户与 JOB No 筛选都跨六表保留。
- 批量录入：在单元格直接粘贴 Excel TSV，多行自动扩展。
- 开票/回款覆盖：在“覆盖批次”按批次选择会带入整批设备；在“覆盖製造番号”按单台设备逐一勾选，可将同一发货批次拆分到不同开票或回款记录。已选番号和批次自动回写，有设备的有效回款不允许空覆盖保存。
- 金额口径：同款类、同设备范围的多笔开票/回款会累计，番号明细仍优先于历史批次兜底，避免重复计算。
- 关联改名：修改合同 JOB、批次名、设备番号或付款条款款类，会根据稳定记录 ID 同步相关表。
- 拆分批次：按型号或单台选择设备移入新批次，自动重算汇总。
- 删除订单：合同页选择 JOB 后两次确认，六表级联删除；取消确认不会发生任何删除。
- 跨表查询：按任意基础表查询并带出合同、批次或付款条件字段，可预览和导出。
- 跨表查询还提供「未付款订单」（按 JOB 汇总）和「未回款明细」（按批次/款类）虚拟数据源；它们与导出台账的未回收管理表使用同一计算口径，按客户筛选即可查到全部相关订单和款项。
- 报价单：来源 JOB 可复用现有订单字段；每条报价明细旁的「历史报价」按规范化后的“同一客户 + 同一型号”查询过去已保存价格，并排除当前报价。

## 技术与目录

```text
data/                  本机唯一工作数据库与 Excel（不上传 GitHub）
releases/macOS/        Mac App、Mac 压缩包及其 data/ 发布副本
releases/Windows/      Windows 可运行目录、压缩包及其 data/ 发布副本
app.py                 pywebview 桌面壳与本地 API
core.py                六表模型、派生、业务校验、台账导出
database.py            SQLite、JSON 迁移、事务、备份与审计
quotation.py           标准报价单 XLSX 生成器
build_ledger_main.py   导航页/未回收表/JOB 页生成引擎
ui/                    HTML / CSS / JavaScript 界面
tests/                 数据库、桌面 API 和生成引擎回归测试
create_portable_starter.py  发布包空白 DB/XLSX 生成器
```

依赖为 Python 3.11+、pywebview 与 openpyxl。应用界面使用 Kanken 参考色：主蓝 `#004494`、青绿 `#13BCBC`、近黑 `#1C1C1C`，字体优先 `Noto Sans SC` 并提供系统中文字体回退。

## 命令行与验证

```bash
python app.py --database "/path/ledger.db"
python -m unittest discover -s tests -v
node --check ui/app.js
```

旧参数 `--store /path/ledger.records.json` 与环境变量 `BKTC_STORE` 仍兼容，会迁移为同目录 `.db`。新部署建议使用 `--database` / `BKTC_DATABASE`。

## 数据与发布

真实 `.db`、`.db-wal`、`.db-shm`、`*.records.json`、`.xlsx` 与 `备份/` 已被 `.gitignore` 排除，客户数据不会上传 GitHub。程序会优先使用可执行文件旁的 `data/`；本机源码和 Mac App 会固定使用项目内 `BKTC_Ledger/data/`，不会把 `/tmp` 临时路径当作长期数据库。GitHub Actions 在 macOS/Windows 上先执行回归测试，再打包应用；tag `v*` 会创建 Release。公开构建使用空白启动数据库，本机交付包再放入项目 `data/` 的当前数据库与台账，避免把客户数据上传 GitHub。
